# Smart Adaptive Intake — Plan

Refactor `intake.$token.tsx` into a low-friction, branching, AI-assisted flow that works for both **PT-guided** and **self-guided** users, with skippable questions and a coach visibility layer.

---

## 1. Path selection (new first slide, after Welcome)

Add a "Quem é isto para?" slide:
- **Treino com PT** → keeps current flow, asks identity + scheduling + equipment in detail.
- **Treino sozinho/a** → simpler explanations, AI does more interpretation, hides PT-only fields (e.g. "scheduling for sessions with PT"), shows lighter copy.

Stored in `extended.intake_path = "coached" | "self"`.

When the link is generated by a coach (current invite flow) the default is `coached` — but the client can still flip it to `self` if needed (e.g. friend test). When a future self-serve onboarding lands, default flips to `self`.

## 2. Universal "Skip / I don't know" affordance

Every non-critical slide gets:
- a small **"Saltar"** ghost button next to the primary CTA (advances without setting value).
- skipping records `extended.skipped[<field>] = true` so the coach dashboard can flag it.

Critical-path validation is reduced to:
- Identity (name + email)
- PAR-Q answers (safety; can't skip — but each answer can be "Não sei" → treated as `true` for safety)
- Goal "what" (free text — no format required)

Everything else is skippable.

## 3. AI Interpretation Layer

New server function `interpretGoal` in `src/server/intake-ai.functions.ts`:
- Input: free text like "tone", "be healthier", "ficar mais forte".
- Calls Lovable AI Gateway (`google/gemini-3-flash-preview`) with a structured-output tool returning:
  ```
  { intent: "fat_loss"|"hypertrophy"|"strength"|"endurance"|"general_health"|"mobility",
    measurable_suggestion: string,
    timeline_weeks: number,
    confidence: 0..1,
    notes: string }
  ```
- Stored in `extended.ai_goal_interpretation`. Never shown raw to the client — used silently by the coach + plan generator. On the coach side (`clients_.$clientId.tsx` intake review) it surfaces as "Interpretação da IA · editar".

For **self-guided** users only, after the goal slide we show a soft confirmation: *"Soa-me a __ganho de força geral__. Faz sentido?"* with Yes / "Não, é outra coisa" → reopens textbox. Coached users skip this confirmation (the coach validates).

## 4. Adaptive branching (replaces the linear 17-slide loop)

Slides are filtered at runtime by predicates:
- **Equipment slide** only if `training_location ∈ {Home, Outdoor, Mixed}` (gym = assume full kit; ask only "ginásio comercial vs box/CrossFit vs studio").
- **Scheduling slide** (new — PT path only): "Que dias e horas tens disponíveis?" with day chips + free-text time band.
- **Injuries deep-dive** appears only if injuries free-text is non-empty OR if user hits "tenho algumas dores" toggle.
- **Lifestyle / Nutrition** sections are collapsed into a single optional "Queres responder a mais umas para o teu treinador ter contexto?" gate — skipping marks them all skipped at once, so the form ends faster.

Result: minimum path ≈ 6 slides (welcome + path + identity + PAR-Q + goal + review). Maximum ≈ same as today.

## 5. Coach visibility layer

In `clients_.$clientId.tsx` (intake summary card), add a **"Dados em falta"** chip row:
- one chip per skipped field (amber) + per "Não sei" PAR-Q answer (red).
- click chip → opens trainer-side editor for that field (already exists for most; wire missing ones).
- AI goal interpretation shown inline with "editar" pencil; trainer edits set `provenance.smart_goal = "trainer-edited"` (existing mechanism).

Dashboard "Atenção" panel: an item per client with `> 3` skipped critical fields.

## 6. Future-ready schema (no migration beyond what's needed)

Everything new lives inside the existing `assessments.extended` JSONB:
- `intake_path`, `skipped`, `ai_goal_interpretation`, `scheduling`, `injuries_detail[]`, `lifestyle_extras`, `nutrition_extras`.

No DB migration required for v1. (Optional later: promote `intake_path` to a real column for indexing.)

## 7. Bug fixes (drive-by, in scope)

- **Broken trainer logo** in intake header (screenshots) — `ctx.trainer.logo_url` is null for this trainer; fall back to `BrandMark` (Forge logo) instead of `<img src="">`.
- **i18n leaks** on slides 3 & 4 ("How will you measure success?" / "By when?" in PT screenshots) — extend `pt/intake.json` with the missing keys; also fix EN string `"Step {{current}} of {{total}}"` already present but verify slide titles are translated.
- **Auto-advance**: pills (single-select) auto-advance after 250 ms unless on the last critical slide.
- "Skip" / "Não sei" labels added to `intake.json` (PT + EN).

## 8. Non-goals for this PR

- Building self-serve signup. (Path selector is wired; flipping to `self` just adapts copy.)
- Voice-to-intake, sleep tracker integrations, mental/behavioural inventory — schema is ready but UI deferred.
- Client-side login (still token-based intake link).
